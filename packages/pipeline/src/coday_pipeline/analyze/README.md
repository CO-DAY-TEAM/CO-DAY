# analyze

### 1. 폴더 구조 세분화
- 수집 → 필터링 → diff 파싱·검증 → 전체 PR 입력 구성의 흐름
- 장점: 파일마다 하는 일이 하나라 읽기 쉬움

```
analyze/
├── __init__.py        # 공개: analyze 하나만
├── service.py         # 진입 함수 analyze(): 수집·파싱·검증·입력 구성
├── collector.py       # GitHub PR patch와 관련 코드 수집
├── diff_parser.py     # patch 문자열 → hunk와 줄 번호
├── file_filter.py     # 리뷰할 파일인지 판단
└── tests/
    ├── test_diff_parser.py
    └── test_file_filter.py
```

Analyze에서 파싱한 hunk와 줄 정보를 파일별로 묶어 Judge에 전달합니다.

### 2. `service.py`에 넣지 말아야 할 것

- **GitHub API 호출 코드를 직접 작성하기**: HTTP 요청 같은 공통 인프라는 `coday_core/github.py`에 두고, `service.py`는 가져다 쓰기만 합니다.
- **다른 단계 호출**: `analyze()` 안에서 `judge()`를 부르면 안 됩니다. 단계를 잇는 건 워커의 몫입니다.
- **dict를 그대로 주고받기**: 단계 바깥과 주고받는 데이터는 반드시 `contracts` 스키마로 합니다.
- **`if __name__ == "__main__":` 실행 코드**: 수동 실행은 `scripts/`에 따로 만듭니다.


관련 파일은 변경 줄에 이름 또는 리터럴 경로가 나타나는 직접 로컬 import, 그 밖의 직접 로컬 import,
기존 파일명 유사도, 같은 디렉터리 순으로 선정합니다. 이름 참조는 정적 식별자 비교이며
정확한 호출 그래프나 심벌 해석을 보장하지 않습니다.
Python은 AST와 실제 패키지 경로를, JS/TS는 정적 상대 import와 literal require를 사용합니다.
외부 패키지·계산된 import 경로·모호한 확장자 해석은 추측하지 않습니다.
변경 파일의 PR HEAD 원문을 제한 내에서 읽어 import를 확인합니다. 파일 전체를 그대로
추가하지는 않으며, 아래의 변경 함수 문맥을 별도로 제공합니다. 관련 파일의 전체 본문 전달,
최대 5개 기본값, 제외 규칙과 크기 한도는 유지합니다.
ReviewBench 어댑터도 동일한 경로 해석·우선순위 함수를 사용합니다.

Helm chart의 values/템플릿 변경과, 변경된 Argo Application/ApplicationSet의 명시적인
`source.path`·`helm.valueFiles` 연결도 관련 템플릿 선정에 사용합니다. 같은 저장소임이
확인되는 참조만 따라가며 디렉터리 생성기는 `.path.basename`·`.path.path` 치환만 지원합니다.
외부 저장소, `$values`, 알 수 없는 템플릿 변수·generator 제외 조건은 추측하지 않습니다.
삭제된 values도 변경 경로와 대조할 수 있지만 순수 rename의 검토 범위는 확장하지 않습니다.

기본 관련 문맥 5개·파일당 18,000바이트 제한은 유지합니다. 변경 patch의 바이트를 먼저
예약하고 남은 입력 예산에 맞는 후보를 선정합니다. 빈 파일은 제외하며, 읽은 내용이
비텍스트/크기 초과이면 다른 후보로 보충하되 관련 본문 읽기는 파일 수 제한의 2배 이내입니다.
운영 collector와 평가 어댑터는 같은 참조 해석·순위 함수를 사용합니다.
Go import와 CSS 변수 정의 탐색은 포함하지 않습니다.

변경 함수 문맥은 Python AST와 JS/TS/JSX/TSX의 Tree-sitter 구문 트리로 추출합니다.
변경 줄을 포함한 가장 안쪽 함수를 선택하고, 겹치는 구간을 병합합니다. 함수의 HEAD 줄 번호와
본문이 diff와 일치하는지 확인한 뒤 이미 diff에 있는 줄은 다시 보내지 않습니다. 나머지는
`fragments`에 시작/끝 줄과 함께 넣고, diff로 제공한 구간은 `diff_ranges`로 표시합니다.
조각만으로는 완전하지 않으므로 `complete=false`, diff와 합치면 함수를 복원할 수 있으므로
`complete_with_diff=true`로 전달합니다. 함수 전체가 diff에 있으면 별도 문맥을 추가하지 않습니다.
HEAD 경로·SHA·함수 전체 범위를 함께 제공하며, 게시 가능한 지적 위치는 변경 줄로 제한합니다.

기존 diff와 관련 파일을 먼저 보존하고 남은 입력 예산만 사용합니다. 기본 함수 문맥은
최대 5개 변경 파일, 파일별 누적 18,000바이트, 전체 90,000바이트 이내입니다.
직렬화한 함수 메타데이터도 예산에 포함합니다. 큰 함수는 중간을 자르지 않고 제외하며,
미지원 언어·파싱 실패·원문 읽기 제한·중복·문맥 예산 초과 사유를 기록합니다.
운영에서는 선택 내역을 로그에, 평가에서는 `raw-review.json`에 저장합니다.
함수 추출은 import 분석 때 읽은 HEAD 원문을 재사용하므로 추가 파일 조회가 없습니다.
다른 언어의 함수 추출과 재귀적인 호출 대상 추적은 이번 범위에 포함하지 않습니다.

JS/TS import 탐색도 구문 트리를 사용하여 중첩 템플릿·주석·문자열 예시를 실제 import와
구분합니다. 동적 import는 변경부에 고정 문자열로 명시된 `import('...')`만 추적하며
변수·문자열 조합·템플릿 경로는 추측하지 않습니다. 여러 import가 같은 경로를 가리키면
하나의 후보로 합치고 기존 관련 파일 수·바이트 예산 안에서 선정합니다.

경로 별칭은 가장 가까운 `tsconfig.json` 또는 `jsconfig.json`의 명시적인 `paths`와
`baseUrl`만 해석합니다. JSONC 주석·후행 쉼표와 단일 대상의 정확한/별표 하나 매핑을
지원하며 `@/`를 특정 디렉터리로 하드코딩하지 않습니다. `extends` 상속, 다중 대상,
모호한 파일 후보와 저장소 밖 경로는 해석하지 않고 기록합니다. 설정은 PR HEAD의 일반
파일에서만 읽고, 제외 규칙·파일당 크기·원문 읽기 예산을 지킵니다. 설정 조회는 기본 최대
5개 파일, 파일당 18,000바이트이며 실패한 가까운 설정을 무시하고 상위 설정으로 추측하지 않습니다.
